# Spec: Structured Agent Runtime — each provider speaks its own machine protocol

Supersedes the hidden-PTY transport for claude/codex/gemini (antigravity, which
is not user-exposed, remains on `hidden_pty`). The PTY-era prompt pipeline spec
(`agent-prompt-pipeline.md`) still governs the SERVICE model (queue, lifecycle,
identity); this spec replaces its *detection* layer (scrape/hooks) with native
protocol events.

## Why

A week of live failures (double cards, fused box text, the second box never
surfacing, batched permissions hanging, instant answers typed into not-yet-
painted boxes) were all consequences of one choice: wrapping interactive TUIs
in a hidden PTY and INFERRING events from screen scrapes, hook spools, and
history-file polling. All three CLIs ship structured machine interfaces built
for exactly our use case — their own IDE integrations use them. Tide now uses
them too. There is NO fallback path: one engine per provider.

## Evidence discipline

Every protocol fact in the clients is evidence-based: live transcripts captured
against the installed CLIs (under `/tmp/tide-proto-evidence/<provider>/` at
research time), machine-generated bindings (`codex app-server generate-ts`),
and the open-source gemini bundle. The client files carry the facts as header
comments. **Never extend a client from memory of "how the protocol probably
works" — capture a transcript first.** Known empirical traps already encoded:

- claude emits NOTHING (not even its init line) until the first stdin message —
  write the first turn immediately at spawn or both sides deadlock.
- claude requires the hidden flag `--permission-prompt-tool stdio` for
  can_use_tool permission requests; without it tools are silently auto-blocked.
- codex app-server is JSON-RPC-SHAPED but never emits a `jsonrpc` field; the
  server sends REQUESTS (approvals) from its own id namespace.
- gemini ACP generates the session id agent-side (no minting); an untrusted cwd
  SILENTLY skips MCP servers — `GEMINI_CLI_TRUST_WORKSPACE=true` is the
  source-verified override (trust remains a Tide product decision).

## Architecture

```
AgentIntegrationPort.buildStartPlan/buildResumePlan
  └─ ProviderLaunchPlan { transport, protocolParams, args, env, cwd }
       transport: hidden_pty (antigravity) | claude_stream_json |
                  codex_app_server | gemini_acp

AgentIntegrationAgentRuntimePort (provider-neutral)
  ├─ hidden_pty  → PTY spawn + scrape/hook/history machinery (legacy)
  └─ structured  → per-provider protocol client
       └─ emits StructuredProviderEvent:
            session_ref | content_record | prompt | prompt_withdrawn |
            turn_completed (notice?, usage?) | runtime_exited

live-backend projector.ingestStructuredProviderEvent
  ├─ content_record → appendFrameAndEmit (same frame→block reader as ever)
  ├─ prompt         → emitPromptState (service queue handles multiplicity)
  ├─ turn_completed → ingestTurnOutcomeAndSettle (+ usageChanged)
  ├─ session_ref    → recordDiscoveredProviderSessionRef
  └─ runtime_exited → settle (a crash never strands "Working")
```

NO pollers exist for structured runtimes — the protocol pushes. The PTY-era
pollers attach only via `onRuntimeStarted`, which the structured spawn path
never calls.

## Per-provider transport table

| | claude | codex | gemini |
|---|---|---|---|
| spawn | `claude --print --input-format stream-json --output-format stream-json --verbose --permission-prompt-tool stdio …` | `codex app-server` (+`-c` overrides for Tide MCP) | `gemini --acp` |
| framing | JSONL, not JSON-RPC | JSONL, JSON-RPC-shaped (no `jsonrpc` field) | JSON-RPC 2.0 JSONL |
| session id | minted `--session-id`, confirmed by init | thread/start result (id + rollout path) | generated by agent (session/new result) |
| user turn | user message line on stdin (process persists) | `turn/start` | `session/prompt` (open until turn ends) |
| content | assistant/user message lines (complete messages) | `item/completed` notifications | `session/update` chunks (accumulating upserts → streaming) |
| permission | `control_request: can_use_tool` → `control_response` allow/deny; AskUserQuestion carries options, answered via `updatedInput.answers` | server request `item/*/requestApproval` → `{decision}` | server request `session/request_permission` → `{outcome:{outcome:"selected", optionId}}` |
| turn end | `result` message (usage + modelUsage.contextWindow) | `turn/completed` (+tokenUsage/updated) | `session/prompt` resolution (`stopReason`, `_meta.quota`) |
| resume | `--resume <id>` at spawn | `thread/resume` in protocol | `session/load` in protocol |
| trust | non-TTY mode skips the dialog by design; Tide trust flow stays | no trust gate in protocol (sandbox/approval is the model) | forced via `GEMINI_CLI_TRUST_WORKSPACE=true` |
| auth failure | result `is_error` + "Not logged in" synthetic message | 401 error notifications (preflight gates earlier) | session/new error -32000 |

## What this kills (for the three structured providers)

PTY scraping and ANSI/cursor parsing, keystroke menu navigation and Esc-cancel,
submit-key sequences and startup delays, hook bootstrap + spool polling for
turn-end/permission/binding, history-file polling for live content, the MCP
readiness gate for first-turn handoff, and the entire "Working forever because
a box was missed" failure class. The service-level prompt QUEUE remains — the
structured protocols also issue multiple concurrent interactions.

Hook/bootstrap artifacts are still written but no longer read for these
providers; deleting that machinery (and the PTY-only adapter code) is tracked
as the dead-transport cleanup task.
